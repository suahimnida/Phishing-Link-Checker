# 서비스 운영 절차

일회성 프로젝트가 아니라 계속 정확해지는 서비스가 되기 위한 운영 절차다.
핵심은 **피드백 수집 → 검토 → 데이터 갱신 → 재학습 → 정확도 개선**의 순환 구조다.

## 1. 순환 구조

| 단계 | 하는 일 | 도구 | 주기 |
|---|---|---|---|
| 수집 | 결과 화면의 "이 판정이 틀렸나요?"로 신고를 받는다 | `POST /api/v1/analyses/{id}/feedback` | 상시 |
| 검토 | 신고를 사람이 확인하고 승인·거절한다 | `scripts/review_feedback.py` | 주 1회 |
| 데이터 갱신 | 승인된 신고를 블랙리스트 예외·추가 목록과 학습 라벨에 반영한다 | `review_feedback.py accept` | 검토 때 |
| 목록 점검 | 블랙리스트·허용 목록의 품질과 만료 도메인을 점검한다 | `scripts/audit_lists.py --online` | 월 1회 |
| 재학습 | 기존 데이터 + 검토된 신고 라벨로 모델을 다시 학습한다 | `build_training_set.py` → `train_url_model.py` | 월 1회 |
| 검증 | 평가 세트에서 기존 모델과 비교해 나빠지지 않았을 때만 교체한다 | `scripts/evaluate_model.py` | 재학습 때 |

### 신고를 자동으로 반영하지 않는 이유

공격자가 자기 피싱 사이트를 "실제로는 안전"이라고 반복 신고하면 허용 목록이나 학습 데이터가 오염된다.
그래서 모든 신고는 `pending`으로 저장되고, 사람이 승인해야만 반영된다.
서버도 같은 사용자의 신고를 결과 하나당 1건, 하루 20건으로 제한한다.

검토 때 확인할 것은 `scripts/review_feedback.py` 맨 위의 체크리스트에 있다.
같은 도메인에 짧은 시간 동안 신고가 몰리면 조작 신고를 의심한다.

### 승인하면 어디에 반영되나

| 신고 | 원인 | 반영 위치 | 서비스 반영 시점 |
|---|---|---|---|
| 실제로는 안전 | KISA 목록 일치 | `resources/blacklist/exclusions.txt` | 다음 배포 |
| 실제로는 안전 | 모델 점수 | `data/feedback_labels.csv` (정상) | 다음 재학습 |
| 실제로는 피싱 | 놓침 | `resources/blacklist/additions.txt` + `data/feedback_labels.csv` (피싱) | 다음 배포 (목록), 재학습 (모델) |

학습 라벨에는 URL의 `?` 뒤를 빼고 저장한다 (개인정보 보호).

## 2. 재학습 절차와 교체 기준

```bash
python scripts/build_training_set.py      # data/feedback_labels.csv 가 있으면 자동으로 포함
python scripts/train_url_model.py
python scripts/evaluate_model.py          # evaluation/results/ 에 지표 저장
```

새 모델은 아래를 모두 만족할 때만 교체한다.
- 평가 세트의 미탐률(피싱을 정상으로 판정)이 기존보다 높아지지 않을 것
- 오탐률(정상을 피싱으로 판정)이 기존보다 높아지지 않을 것
- 검토된 신고 URL을 신고 내용대로 판정할 것

평가 세트와 같은 도메인의 신고는 학습에서 빼서, 평가 점수가 부풀지 않게 한다.

## 3. 블랙리스트·허용 목록 관리

- **블랙리스트 갱신**: KISA 피싱 사이트 URL 공개 데이터가 갱신되면 `scripts/build_blacklist.py`로 다시 만든다.
  현재 기준일은 2024-12-31이며 결과 화면에 표시된다 (`blacklist.SOURCE_DATE`).
- **공용 주소 예외**: KISA 목록에는 카카오톡 채널(`pf.kakao.com`), 국민건강보험공단(`www.nhis.or.kr`)처럼
  플랫폼이나 사칭 대상 주소가 호스트 단위로 섞여 있다. 서비스는 공식 도메인과 플랫폼 주소를 호스트 단위로
  확정하지 않고, 경로까지 일치하는 신고 페이지만 확정한다. 그 밖의 공용 주소는 `exclusions.txt`에 검토 후 추가한다.
- **허용 목록 점검**: 만료된 공식 도메인은 다른 사람이 다시 등록해 피싱에 쓸 수 있다.
  `audit_lists.py --online`에서 등록 정보·DNS가 없는 도메인을 확인해 허용 목록에서 뺀다.

## 4. LLM 비용과 응답 시간

- **위험·주의 판정에만 LLM 설명**을 만든다. 정상 판정과 KISA 목록 확정은 템플릿 설명을 쓴다.
- **설명 캐시**: 같은 근거·가이드 조합이면 24시간 동안 이전 설명을 재사용한다 (서버 메모리, 최대 500건).
  키는 URL이 아니라 근거 문장의 해시다. 출처 검증을 통과한 설명만 저장한다.
- 적중·호출 횟수는 `/health`의 `llm.claude.cache`에서 확인한다.

## 5. 개인정보

| 항목 | 내용 |
|---|---|
| 저장하는 것 | 입력한 URL, 분석 결과, 공개 여부, 브라우저 식별값(무작위 ID), 선택 시 가린 이름과 암호 해시, 신고 내용 |
| 저장하지 않는 것 | 의심 사이트의 내용(접속하지 않음), IP 주소(분석 기록에 저장하지 않음) |
| 보관 기간 | 분석 후 90일 (`RETENTION_DAYS`). 지나면 분석 기록과 리포트·공유 링크·본인 확인·신고를 함께 삭제 |
| 삭제 시점 | 서버 시작 때와 이후 하루 한 번 |
| 로그 | URL의 `?`·`#` 뒤를 가리고 남긴다 (`privacy.mask_url`) |
| 신고 활용 | 검토 후 블랙리스트·학습 데이터 개선에만 쓴다. 학습 라벨에는 `?` 뒤를 빼고 저장 |
| 사용자 안내 | 결과 화면 하단 "개인정보 처리 안내", 분석 입력란 아래 안내 문구 |
